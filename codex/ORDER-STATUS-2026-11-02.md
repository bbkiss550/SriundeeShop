# เปลี่ยนขั้นตอนสถานะคำสั่งซื้อ

| ID | สถานะ | ขั้นตอนถัดไป |
| --- | --- | --- |
| 0 | ยกเลิก | ไม่เปลี่ยนสถานะจากหน้าปกติ |
| 1 | รอกดของ | 1 → 2 บันทึกต้นทุนตามเดิม |
| 2 | รอเว็บส่งของ | 2 → 3 บันทึกเลข Lot และช่วงวันที่คาดว่าจะถึงไทย |
| 3 | รอของถึงไทย | 3 → 4 เปลี่ยนสถานะอย่างเดียว ใช้ Lot เดิม ไม่สร้าง Lot หรือค่าใช้จ่ายใหม่ |
| 4 | รอของถึงร้าน | 4 → 5 บันทึกค่าขนส่งและวันที่ถึงร้านตามเดิม |
| 5 | ถึงร้านแล้ว รอส่ง | 5 → 6 บันทึกค่าส่งไปรษณีย์ตามเดิม |
| 6 | ส่งแล้ว | ล็อกการเปลี่ยนสถานะตามเดิม |

## ข้อมูลเดิม

สีสถานะใช้ token `order-status-0` ถึง `order-status-6` ใน `os_color` และกำหนดสีใน `static/css/order-status.css` ร่วมกันทั้งปุ่มกรองและป้ายสถานะทุกหน้าที่ใช้สีจากตารางนี้

| ID | สี |
| --- | --- |
| 0 | #DC3545 |
| 1 | #D99A00 |
| 2 | #EA580C |
| 3 | #7C3AED |
| 4 | #0284C7 |
| 5 | #435EBE |
| 6 | #15803D |

ปุ่มที่ยังไม่เลือกเป็นกรอบสี ปุ่มที่เลือก/ชี้เมาส์เป็นพื้นสีเต็ม ใช้ตัวหนังสือเข้มบนสีอำพัน ส้ม และฟ้าเพื่อให้อ่านชัด ส่วนสีอื่นใช้ตัวหนังสือขาว รองรับ Light/Dark, focus ด้วยคีย์บอร์ด และ reduced motion

เมื่อเริ่มโปรแกรม `LoginDatabaseInitializer` เรียก `OrderStatusMigration` ภายใน transaction โดยใช้ `db/order-status-thailand.sql`

- รายการเก่า ID 3, 4, 5 ย้ายเป็น 4, 5, 6 ตามลำดับ เพื่อรักษาขั้นตอนเดิม
- ID 0, 1, 2 ไม่ขยับ โดย ID 2 เปลี่ยนชื่อเป็น “รอเว็บส่งของ”
- รันซ้ำได้ โดยตรวจสอบชื่อและ ID ครบชุดก่อนข้าม migration; หากพบชุดสถานะไม่ตรงตามที่รองรับ จะหยุดแทนการเดาและแก้ข้อมูล
- ไม่เพิ่มตารางหรือคอลัมน์ ไม่เปลี่ยนเลข Lot และไม่สร้างค่าใช้จ่ายย้อนหลัง
- การยกเลิก/ลบรายละเอียด Lot คืนสถานะเป็น 2 และยกเลิกค่าขนส่งคืนเป็น 4; เงื่อนไขยกเลิกค่าขนส่งตรวจสถานะ 5
- รายงานนับเข้า Lot ตั้งแต่ 3, ถึงร้านตั้งแต่ 5 และส่งสำเร็จที่ 6

## ทดสอบโดยไม่เขียนคำสั่งซื้อจริง

```powershell
.\mvnw.cmd '-Dtest=ChangeControllerTest' test
node scripts/test/change-status.cjs
```

ทดสอบ SQL จริงบน PostgreSQL ด้วยตารางชั่วคราวที่ rollback ทั้งหมด: ข้อมูลเก่า 0,1,2,3,4,5 กลายเป็น 0,1,2,4,5,6, รันซ้ำไม่ขยับซ้ำ, คงสีขั้นตอนเดิม และปฏิเสธชุดสถานะที่ไม่รองรับ

ก่อนใช้กับฐานข้อมูล localhost สำรอง ID และสถานะเดิมไว้ใน `.runtime/db-backups/status-before-2026-11-02.sql` (ไฟล์ส่วนตัว ไม่ commit)
