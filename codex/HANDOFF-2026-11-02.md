## งานที่ส่งมอบ

### 1. หน้าตั้งค่าสินค้า

- ใช้ Modal หลัก แบ่งเป็น 3 ขั้นตอน: ภาพ/ข้อความ → ข้อมูลสินค้า → เว็บ/เวอร์ชัน/ปก/ราคา
- กรอกข้อมูลสินค้าและจัดราคาทุกตัวเลือกก่อนบันทึกพร้อมกัน
- ฟอร์มข้อมูลสินค้าปรับกลับให้ใกล้รูปแบบเดิม: เรียงแนวตั้ง, Label พื้นฟ้าอ่อนติดช่องกรอก และ Checkbox ไม่มีกำหนดอยู่ท้ายช่องวันที่
- ปุ่มเพิ่มประเภทและศิลปินเป็น `＋` สีเขียวต่อท้าย Dropdown
- เพิ่มประเภทหรือศิลปินจากหน้าต่างย่อยได้ และเลือกค่าที่เพิ่มให้ทันที
- ศิลปินและเว็บไซต์มีช่องค้นหา พร้อมเพิ่มข้อมูลจากหน้าที่ใช้งาน
- หลังบันทึกสินค้าสำเร็จ: ปิด Modal → แสดง SweetAlert → กดตกลงแล้วรีเฟรชหน้ารายการ
- หากบันทึกไม่สำเร็จ จะคงฟอร์มและข้อมูลไว้ให้แก้ไข/ลองใหม่

### 2. จัดการราคาแบบกลุ่ม

- โครงสร้าง: กลุ่มเว็บไซต์ → เวอร์ชัน → ปก → ราคาเต็ม/มัดจำ/คงเหลือ
- กลุ่มเดียวเลือกได้หลายเว็บไซต์ และใช้รายการราคาเดียวกัน
- เพิ่ม ลบ และคัดลอกเวอร์ชัน/ปกได้
- คงเหลือคำนวณจากราคาเต็มลบมัดจำ
- Accordion เปิดได้ทีละรายการในแต่ละระดับ และรักษาข้อมูลเมื่อยุบ
- มี Animation ยุบ/ขยาย และรองรับ reduced motion
- เปลี่ยนกลุ่มแล้วปิดเวอร์ชัน/ปกเดิม; เปลี่ยนเวอร์ชันแล้วปิดปกเดิม
- ปุ่มควบคุมหลักใช้เปิดกลุ่มแรกและยุบทั้งหมด
- จัดการเว็บไซต์ด้วย Modal: ล็อกหัว/ท้าย และเลื่อนเฉพาะรายการ Checkbox
- รองรับ Light/Dark และหน้าจอขนาดเล็ก

### 3. นำเข้าจากภาพและข้อความ

- เลือกได้ระหว่างอ่านจากภาพกับวางข้อความ
- ภาพรองรับ PNG/JPEG ไม่เกิน 8 MB, วางจาก Clipboard และ Crop
- ส่งอ่านเฉพาะภาพส่วนที่ Crop พร้อมปุ่มหยุดและ Progress เป็นเปอร์เซ็นต์
- ถ้าเปิดใช้ AI ที่ตั้งค่าและทดสอบแล้ว จะเรียก AI จาก Backend
- ถ้า AI ไม่พร้อม/โควตาหมด/429/Timeout/ผลลัพธ์ไม่ผ่านการตรวจ จะใช้ OCR ภายในเครื่องสำรอง
- โหมดวางข้อความใช้กฎจัดกลุ่มในระบบ ไม่ต้องอัปโหลดภาพ
- แสดงแหล่งอ่านจริงว่า AI, OCR หรือจัดกลุ่มข้อความ
- ก่อนเติมลงฟอร์ม มีตาราง: เว็บ / เวอร์ชัน / ปก / ราคาเต็ม / มัดจำ / คงเหลือ
- ตรวจแก้ข้อความแล้วจัดกลุ่มใหม่ได้ ผลลัพธ์ยังไม่บันทึกสินค้าจนกดบันทึกเอง
- มัดจำที่ไม่ได้ระบุใช้ 0; มัดจำที่ระบุไว้แต่อ่านไม่ชัดยังเว้นให้ตรวจแก้
- หากไม่มีเวอร์ชันใช้ `Standard`; หากไม่มีเว็บใช้รายการอ้างอิง `ไม่มีเว็บ`
- เว็บที่อ่านพบแต่ยังไม่มีในระบบสามารถเพิ่มจากหน้าผลอ่านได้

### 4. กฎอ่านที่แก้ไขล่าสุด

| ลักษณะข้อมูล | ผลที่ต้องได้ |
|---|---|
| รายการเดี่ยวที่ไม่ได้ระบุชื่อและมี SET คู่กันในเวอร์ชัน/เว็บเดียวกัน | ชื่อปก `สุ่ม` |
| ชื่อปกที่ระบุชัดเจน | รักษาชื่อเดิม |
| `ระบุปก Fallen Angel / Alt ver.` | แยกปก Fallen Angel และ Alt; ไม่สร้างสองเวอร์ชัน |
| `สุ่มปก Fallen Angel / Alt ver.` | เป็นรายการสุ่มเดียว |
| SET ตามหลังรายการปก | เพิ่มครั้งเดียวในกลุ่มเว็บและเวอร์ชันนั้น |
| ชื่อเวอร์ชันที่มี `[ ]` หรือ `( )` หลายชุด | เก็บชื่อครบและแยกเวอร์ชันได้ |
| `SET(5)`, `DAY SET(6)`, `NIGHT SET(6)` | เก็บจำนวนในชื่อ ไม่ใช้จำนวนเป็นราคา |
| `MEMBERSHIP 610`, `KIT 900` | อ่านชื่อรายการกับราคาได้ แม้ไม่มีคำว่าราคา/มัดจำ |
| ชื่อเว็บเดี่ยวที่ไม่รู้จัก เช่น `TBLshop` | เก็บชื่อเว็บให้ตรวจ/เพิ่ม ไม่เปลี่ยนเป็นไม่มีเว็บ |
| เว็บท้ายราคา | ย้ายขอบเขตให้ได้เฉพาะบล็อกที่ระบุได้ชัดเจน ไม่มีเว็บอื่นหรือข้อความขัดแย้ง |
| ภาพสองคอลัมน์ราคา | อ่านบนลงล่างทีละคอลัมน์ ไม่รวมเว็บทั้งสองฝั่ง |
| รายการหลายเวอร์ชันซ้ำกันใต้คนละกลุ่มเว็บ | รักษาราคาของแต่ละกลุ่ม ไม่ยืมเว็บข้ามกลุ่ม |
| หัวข้อเดี่ยว `ไม่มีการ์ดเบเน` / `ไม่มีเบเน` / `ไม่มี POB` / `No benefit` | เริ่มขอบเขตใหม่; ถ้าไม่ระบุเว็บใหม่ให้ใช้ไม่มีเว็บและแจ้งตรวจทาน |
| `Ktown4u ไม่มี POB` ในบรรทัดเดียวกัน | ยังใช้ Ktown4u เพราะระบุเว็บชัดเจน |
| `2 บั้ม ราคา 780 (มัดจำ400)` | ปก `SET(2)` ราคา 780 มัดจำ 400 ไม่หารราคาและไม่แตกเป็นสองแถว |

OCR รองรับรูปคำตกหล่นที่พบจริง เช่น `s=7(2)`, `=7(2)`, `se7(2)` และ `2 บม ราคา ...` โดยแยกจำนวนออกจากราคา

เพิ่มการอ่านซ้ำจากพิกเซลเฉพาะบรรทัดสำหรับราคาที่ขัดกับมัดจำ และหัวเวอร์ชันที่มีความมั่นใจต่ำ ไม่มีการดึงภาพนอกกรอบหรือดาวน์โหลดข้อมูลระหว่าง OCR

- ไม่แก้ย้อนหลังสินค้าที่บันทึกไว้เมื่อปรับกฎอ่าน ผู้ใช้ต้องอ่าน/จัดกลุ่มใหม่เพื่อตรวจและบันทึกการเปลี่ยนแปลงเอง

## แนวทางทำงานต่อ

1. ตรวจ `git status` ก่อนแก้ไข และรักษางานที่มีอยู่ ห้าม reset/revert ทั้ง workspace
2. ใช้ภาพหรือข้อความตัวอย่างที่ผู้ใช้แจ้งมาทำ regression test ก่อนขยายกฎ
3. แยกกรณีผิดตอน OCR, ผิดตอนตีความข้อความ, ผิดผล AI และผิดตอนเติมฟอร์ม
4. หาก AI อ่านสำเร็จแต่ผลไม่ถูก ให้ตรวจ `rawText` และความสัมพันธ์เว็บ/เวอร์ชัน/ปกก่อนแก้ชื่อหรือราคา
5. รักษา Review ก่อนบันทึก ห้ามบันทึกสินค้าอัตโนมัติจากการอ่านภาพหรือจัดข้อความ
6. ตรวจวงเล็บ จำนวน SET ขอบเขตเว็บไซต์ และหัวข้อไม่มีเบเนทุกครั้งที่แก้ Parser
7. ผู้ใช้กำหนดว่า หากต้องควบคุมเครื่อง/เบราว์เซอร์ที่ใช้อยู่ ต้องขออนุญาตก่อน ไม่ใช้สิทธิ์นั้นโดยอัตโนมัติ
8. หากต้องลบข้อมูลอีก ให้ยืนยันขอบเขต ตรวจว่าเป็น localhost และสำรองข้อมูลก่อน

## ข้อจำกัดที่ยังต้องตรวจทาน

- ข้อความที่ไม่มีชื่อเว็บ/เวอร์ชัน หรือมีขอบเขตคลุมเครือ ยังต้องให้ผู้ใช้ตรวจและเลือกเอง
- เว็บไซต์ที่ไม่รู้จักและไม่ได้มีรูปแบบชื่อที่แยกได้ชัดเจน อาจต้องแก้หรือเพิ่มชื่อเอง
- OCR และ AI ยังอ่านชื่อเฉพาะหรืออักขระบางตัวคลาดเคลื่อนได้ ตารางผลอ่านมีไว้ให้ตรวจทานก่อนบันทึก
- รายการสินค้าแบบหลายเมมหรือหลายแบบที่ภาพไม่บอกชื่อ ไม่ควรเดาชื่อสมาชิกหรือแตกตัวเลือกขึ้นมาเอง
- เมื่อทดสอบกับคำสั่งซื้อ/ข้อมูลจริง ต้องรักษาเงื่อนไข reject ทั้งไฟล์และการตรวจครบทุกแถวของ Excel Import
